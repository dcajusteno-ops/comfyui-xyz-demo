# ComfyUI XYZ Demo

## 📖 项目全局简介
ComfyUI XYZ Demo 是一个深度定制的、功能强大的 ComfyUI 前端 Web 管理面板与高级绘图控制台。
旨在极大提升本地大模型（Stable Diffusion 等）的工作流操作效率，将底层复杂的节点连线封装为直观、现代化的 Web UI。

项目基于 **React 19 + Vite 7** 构建，后端通过专门的 Node.js 跨域代理服务与 ComfyUI 原生 8188 端口 API 进行无缝交互。

## 🎯 已开发的核心功能模块 (Core Features)

目前项目已搭建完毕基础架构，并实现了以下核心标签页功能：

### 1. 默认生图 (Default Generation)
- 标准的文生图/图生图控制面板。
- 支持基础模型（Checkpoint）、采样器（Sampler）、调度器（Scheduler）的快捷切换。

### 2. WD1.4 提示词反推 (WD14 Tagger)
- 深度集成 WD1.4 图像反推逻辑。
- 支持直接上传图片并提取对应的正面和负面 Tag。

### 3. 多人工作流 (Multi-character)
- 强大的多角色蒙版控制机制，可以在同一张图中为多个不同角色分配不同的 Prompt。
- 支持画布区域划分与自动组合。

### 4. 高清修复 (Highres Fix)
- 内置针对生成图像的二次放大与细节重绘功能，支持多种重绘算法与放大倍率参数配置。

### 5. XYZ 控制器 (XYZ Plot)
- 参数矩阵网格生成器。可以一次性对比不同步数、不同 CFG、不同采样器甚至不同 LoRA 权重的出图效果。
- **网格无缝导出**：支持一键将跑完的矩阵图像导出合并为高清网格长图。
- **智能信息打标**：如果使用的是提示词生成模式，导出的网格末尾还会智能追加并标明每个生成的具体提示词后缀。
- **(v0.0.2 优化)**：重构了长轴配置界面的 Flex 布局，彻底修复了长列表参数无法正常向下滚动的问题。

### 6. LoRA 管理系统 (Lora Management) - 近期重点优化
- 完善的 LoRA 卡片式展示、分组过滤与检索。
- **智能示例图同步**：
  - **一键拉取（增量同步）**：批量获取封面图和视频，自动跳过本地硬盘中已存在（SHA256匹配）的文件，极致节省带宽。
  - **单独拉取（强制刷新）**：点击单张图片拉取时绕过验证，强制全量下载并覆盖可能损坏的旧文件。
- **文件锁容错机制 (EPERM 免疫)**：彻底解决了 Windows 系统下资源管理器偶尔锁定下载临时文件导致覆盖失败的痛点。

### 7. 高级记事本 (Rich Text Notepad)
- **多笔记管理**：支持无限创建、重命名、删除多个独立的笔记记录，数据直接安全持久化存储在后端 `data/notes.json` 文件中。
- **所见即所得 (WYSIWYG)**：升级为全功能富文本编辑器，支持加粗、标题、列表、**背景高亮标记**等核心排版能力。
- **文档辅助与全屏沉浸**：提供一键复制、插入时间、导出为 txt 文件、以及一键导入本地长篇 `.txt/.md` 文件的能力。并且支持全屏沉浸模式与字号无级缩放，极度适配处理千字复杂长篇提示词的场景。

### 8. 可视化提示词与编辑器 (Prompt Editor & Visual Tag Blocks) - v0.0.3 新增
- **SDWebUI 风格的提示词方块**：输入框下方会自动将逗号分隔的提示词解析为可视化的胶囊方块。完美兼容包含转义字符与嵌套括号的复杂提示词。
- **极速权重调整**：只需点击方块上的 `+`/`-` 按钮即可快速增减词条权重，或在输入框内使用 `Ctrl+↑/↓`，修改会实时双向同步，彻底告别容易数错括号的痛苦。
- **原生 App 级交互体验**：全局禁用了无效的 UI 文本选中，防止误触高亮，只保留必要的参数文字与输入框的可复制权限。

## 🚀 快速开始 (Quick Start)

如果您是首次从 GitHub 拉取或下载本项目的代码，由于庞大的第三方依赖库 (`node_modules`) 已被 Git 忽略，**请务必手动安装依赖**后才能正常启动项目。

1. **克隆项目并进入目录**：
   ```bash
   git clone https://github.com/dcajusteno-ops/comfyui-xyz-demo.git
   cd comfyui-xyz-demo
   ```

2. **安装依赖 (必做)**：
   ```bash
   npm install
   ```

3. **启动开发服务器**：
   ```bash
   npm run dev
   ```
   *(注：在 Windows 环境下也可以直接双击 `run.bat`，它会自动处理端口冲突并自动在浏览器中打开页面)*

## 🛠️ 运维与启动层优化 (DevOps)

为了彻底解决国内 Windows 环境的疑难杂症，项目拥有一个极度硬核的底层启动机制：
- **终极防闪退脚本 (`run.bat`)**：采用纯粹的 Base64 编码封包 PowerShell 核心代码，利用 `certutil` 和 UTF-8 BOM，彻底免疫任何旧版 CMD 导致的中文乱码与闪退 Bug。
- **幽灵进程收割机制与端口转移 (5173 -> 9999)**：
  - **历史背景**：原默认的 5173 端口在频繁的热更新或异常崩溃时，极易产生残留的 Node 幽灵进程占用端口，导致再次启动时被迫顺延至 5174、5175，极其影响体验。
  - **终极解决**：将项目运行端口硬编码转移至低冲突的 **9999**，并在 `run.bat` 中加入了“端口收割者”逻辑。每次启动/重启前，系统会全网段扫描并无情秒杀任何死锁 9999 端口的进程。
- **自动唤醒浏览器**：在 Vite `npm run dev` 准备就绪后，**自动拉起系统默认浏览器**，直达 `http://127.0.0.1:9999`，实现真正的“一键启动”。
